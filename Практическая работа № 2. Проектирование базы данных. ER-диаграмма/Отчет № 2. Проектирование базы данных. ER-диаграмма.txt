Описание таблиц базы данных
1. Таблица user -пользователи
Хранит информацию о зарегистрированных пользователях системы.
•	id -уникальный идентификатор пользователя, первичный ключ.
•	login -логин пользователя.
•	password_hash -хеш пароля.
•	email -электронная почта.
•	phone -номер телефона.
•	role -роль пользователя в системе.
2. Таблица event -мероприятия
Содержит сведения о проводимых мероприятиях.
•	id -уникальный идентификатор мероприятия, первичный ключ.
•	name -название мероприятия.
•	date -дата проведения.
•	place -место проведения.
•	description -описание мероприятия.
3. Таблица status -статусы заявок
Хранит возможные статусы заявок на участие.
•	id -уникальный идентификатор статуса, первичный ключ.
•	name -название статуса.
4. Таблица request -заявки
Содержит заявки пользователей на участие в мероприятиях.
•	id -уникальный идентификатор заявки, первичный ключ.
•	user_id -идентификатор пользователя, внешний ключ.
•	event_id -идентификатор мероприятия, внешний ключ.
•	status_id -идентификатор статуса, внешний ключ.
•	created_at -дата и время создания заявки.
5. Таблица review -отзывы
Хранит отзывы пользователей о заявках.
•	id -уникальный идентификатор отзыва, первичный ключ.
•	request_id -идентификатор заявки, внешний ключ.
•	text -текст отзыва.
•	rating -оценка.
•	created_at -дата и время создания отзыва.
Описание связей между таблицами
1.	user → request -один пользователь может создать несколько заявок. Каждая заявка принадлежит одному пользователю.
2.	event → request -одно мероприятие может иметь несколько заявок. Каждая заявка относится к одному мероприятию.
3.	status → request -один статус может быть назначен нескольким заявкам. Каждая заявка имеет один статус.
4.	request → review -одна заявка может иметь несколько отзывов. Каждый отзыв относится к одной заявке.
